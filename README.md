# 离心机转子配平工作台（Centrifuge Balance Bench）

选择 **8 / 12 / 24 孔**等角环形转子，录入各槽试管重量，实时计算重量矢量和与失衡状态；
超过阈值时，枚举**未锁定槽位之间至多两次交换**的全部方案，推荐失衡最小的方案，支持一键应用并重算。
方案可保存到浏览器并随时载入。

- 前端：React 18 + TypeScript + Vite
- 后端：Node.js + Express（配平枚举服务 `/api/balance`，同时托管生产构建产物）
- 配平算法为前后端**同一份 TypeScript 实现**（`shared/balance.ts`），服务端不可用时前端自动用本地同一算法兜底

---

## 一条命令启动（Docker Compose）

```bash
docker compose up --build
```

容器会自动完成 **依赖安装 → TypeScript 类型检查 → 前端生产构建 → 启动 Node 服务**，无需任何额外初始化步骤。

启动后访问：

> **http://localhost:3001**

- 页面与 API 由同一个 Node 服务在 **3001** 端口提供
- 健康检查：`GET http://localhost:3001/api/health`
- 后台运行加 `-d`：`docker compose up -d --build`；停止：`docker compose down`

> 如端口被占用，修改 `docker-compose.yml` 中 `"3001:3001"` 左侧宿主机端口即可（如 `"8080:3001"`）。

## 本地开发（不用 Docker）

要求 Node.js ≥ 18。

```bash
npm install        # 安装依赖
npm run dev        # 同时启动 API（3001）与 Vite 开发服务器
```

然后访问开发地址 **http://localhost:5173**（`/api/*` 自动代理到 3001）。

生产方式运行：

```bash
npm run build      # tsc 类型检查 + vite 打包到 dist/
npm start          # Node 服务托管 dist/ 与 API：http://localhost:3001
```

算法自检（对径平衡校验 + 400 组随机用例对照暴力枚举）：

```bash
npx tsx scripts/verify.ts
```

## 功能说明

### 1. 槽位录入
- 顶部切换 8 / 12 / 24 孔转子，槽位按等角环形排布（1 号槽朝上，顺时针编号）。
- 每个槽位录入试管重量（克，支持小数）；**空槽按 0 处理**。
- 点击 🔓/🔒 可**锁定/解锁槽位**；锁定槽重量不允许编辑，也不参与任何拖拽换位与交换枚举。
- 支持“全部锁定(有试管)”批量锁定、“载入示例”快速体验、“清空”复位。

### 2. 拖拽换位
- 在环形图上**按住任一未锁定槽拖到另一个未锁定槽**，松开即交换两者重量。
- 拖到锁定槽或槽外无效；当前选中槽以黄色描边标记。

### 3. 实时矢量和与失衡显示
每次输入/换位/锁定/阈值变化立即重算：
- **合力大小** `|Σ wᵢ·vᵢ|`、**方向角**（自正上方顺时针 0–360°）、X/Y 分量；
- 环形图中央的**方向箭头**指向合力方向：绿色 = 阈值内，红色 = 超阈值；
- 虚线圆为**阈值参考圈**（半径按阈值比例缩放），箭头越出圈外即直观表示超阈值；
- 状态条明确显示“✔ 处于阈值内 / ⚠ 超过失衡阈值”以及 `当前值 / 阈值`。

### 4. 配平推荐（超阈值时枚举至多两次交换）
点击“枚举交换方案并推荐”（当前已平衡时也可用来寻找更优方案）：

- 枚举范围仅限**双方都未锁定**的槽位；
- 枚举 **0 次（保持现状）/ 1 次交换 / 2 次互不相交交换**的所有有效候选
  （等重交换会跳过，因为不改变重量布局）；
- 取交换后合力最小的方案为 ★ 推荐，并展示失衡最小的前 10 名及各自改善量；
- **同值方案按交换槽号升序排序**：先比合力，合力相同时按交换槽号序列字典序
  （如 `(#3↔#7)` 排在 `(#3↔#8)` 前；两次交换采用标准形式 `(a,b)(c,d), b<c`），结果确定可复现；
- 显示达到最优值的方案总数与候选总数；
- 点击“**应用**”一键执行交换并自动重算全部矢量与状态；推荐交换在转子图上以蓝色虚线连线高亮。

以 24 孔全部自由为例，共枚举 32,155 个候选：浏览器本地约 10 ms（实时）、服务端约 0.2 s。

### 5. 方案保存 / 载入
- “保存”把当前 **转子规格、各槽重量、锁定状态、阈值** 以自定义名称存入浏览器 `localStorage`，随时“载入”或“删除”；同名保存自动覆盖；
- 工作状态会**自动保存**，刷新或重开页面后可一键“恢复”上次状态；
- 数据仅保存在本地浏览器，不上传服务器（枚举请求除外）。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/balance` | 配平分析（枚举至多两次交换） |

`POST /api/balance` 请求体：

```json
{
  "holes": 8,
  "weights": [12, 0, 11.2, 10.9, 12.05, 0, 11.15, 10.92],
  "locked":  [true, false, false, false, false, false, false, false],
  "threshold": 0.5
}
```

响应包含 `current`（当前合力/方向/分量）、`best`（最优交换与交换后合力）、
`bestCount`（并列最优数）、`totalCandidates`（枚举总数）、`top`（前 10 名）。
参数非法（孔数不是 8/12/24、数组长度不符、阈值为负等）返回 `400` 与中文错误信息。

## 建模与枚举说明

- 槽 `i` 的单位矢量为 `(sin θᵢ, −cos θᵢ)`，`θᵢ = 2πi/N`（1 号槽朝上，顺时针）。
- 一次交换 `a↔b` 对合力的改变量为 `(wₐ−w_b)(vₐ−v_b)`，两次互不相交交换的增量可直接相加，
  因此枚举中无需每次重算 N 个矢量，24 孔三万余候选也可在毫秒级完成。
- 两次交换取四个不同槽 `a<b<c<d` 后枚举三种配对（ab/cd、ac/bd、ad/bc），
  每种四槽组合恰好覆盖三种可能的两两配对，无重复无遗漏（见 `scripts/verify.ts` 的暴力对照）。
